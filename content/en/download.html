0.40.1 - 2026-11-26

Fixed

  • Download Control: Google's own data was taken for a program. Google's web services send some of their data (JSON) as an attachment named response.bin, and in Block mode this was blocked. Parts of Google pages stopped working as a result. Now, when a file's name says program, archive or disk image but its content is plainly text, the content wins. .bin alone no longer means a program; a real program is still recognised by its first bytes.
  • Download Control: compressed transfers. A file sent gzip- or deflate-compressed is now opened far enough to see its first bytes, so a compressed program is recognised as a program as well.

0.40.0 - 2026-11-26

Added

  • Firewall > Download Control - check the files the devices download. Programs, scripts and other file types can be recorded or blocked as they are downloaded, over HTTP and HTTPS.
  • Web proxy: the firewall runs a web proxy on its own address in the internal networks you choose (port 3128). Devices use it once they are set to, for example on a Windows domain with a Group Policy. The panel lists the steps. Devices that are not set to use it are not checked.
  • What the file really is: the decision uses the file's name, the type the site claims, and the first bytes of the file itself. Recognised: Windows, Linux and macOS programs, MSI, APK, JAR, MSIX, ZIP, RAR, 7z, CAB, PDF and Office files. The parts of a web page (scripts, pictures, compressed pages) do not count as downloads.
  • Disguised programs, for example an .exe named .jpg or .pdf, are recognised by their content. They can be blocked whatever file types are chosen.
  • File types: programs and installers, scripts and shortcuts, archives, disk images, documents, video and audio. Programs and scripts are chosen by default.
  • Monitor or Block:
  • Monitor records what would be blocked and blocks nothing. Start with Monitor for a few days.
  • Block replaces the file with a page saying the download is blocked. The page has the block page's design.
  • Bypass list: these sites are never opened and their files are not checked. Use it for banks, government (gov.tr), operating system updates, security software, and apps that accept only their own certificate. A default list can be added with one click.
  • Always allowed: these sites are checked and recorded but never blocked.
  • Downloads tab:
  • shows the time, device, site, file, type, size and result;
  • can be searched and filtered;
  • keeps the records for 1 to 365 days (30 by default).
  • Administrators only, and every look at the records is logged.
  • If the checker stops, downloads go through. Antivirus software on the PCs keeps doing its own checks.
  • System > Certificates > Inspection CA. A certificate authority of its own for Download Control, separate from the Block Page CA. The proxy uses it to open HTTPS.
  • Install it on the devices that use the proxy: download it as .cer for Windows and Group Policy, or as .crt (PEM).
  • The SHA-256 fingerprint is shown so you can compare it on the devices.
  • Its key never leaves the firewall.

Changed

  • An Apply that fails half way is undone at once. If an unexpected error stops an Apply after the current state has been saved, the firewall goes back to it right away instead of waiting for a confirmation. The message says so. If going back fails too, the message says what to run. The log now shows where the error happened.
  • Squid (the web proxy) is now part of the installation.

0.39.0 - 2026-11-23

Added

  • Firewall > Application Control > Rules: block applications. A rule covers interfaces, Stratum categories (VPN and proxies, Social media, Games ...), applications by name (also custom ones), and optionally *encrypted connections without a server name* - typical of VPN and tunnel apps - with devices as exceptions. The first matching rule decides.

QUIC to that server is refused for 10 minutes, so browsers fall back to TCP, where every connection is checked by name. Connections without a server name (VPN tunnels) also block that device from that server for 10 minutes. The device sees "connection reset" at once.

  • AI Assistant: the tool Application usage also lists the rules and what they blocked (read-only).
  • Application Control: block page. A rule in Block mode can show a page saying the site is blocked, instead of a connection error. It names the site, the application, the rule, the device and the time.
  • The firewall's DNS (Unbound) answers the names of what the rule blocks with 198.18.0.1 for the rule's networks (not for its exceptions); the firewall sends web traffic for that address to the block page. QUIC to it is refused, so browsers use HTTPS over TCP at once.
  • HTTPS: the page gets a certificate for the requested name on the spot, signed by the new Block Page CA. Devices that trust the CA show the page; the others a certificate warning - blocked either way.
  • The names come from nDPI's own domain list for each application (about 1 000 domains) and the custom applications.
  • Devices that use another DNS server are still blocked by cutting their connections, as before.
  • Pages shown are counted on the Blocked tab.
  • Application Control > Block page: your own logo and a wide picture across the top (PNG / JPEG / WebP), organisation name, title, texts, contact line, colour, which details are shown and their labels - in any language, with a live preview. Saved changes are in use at once, without Apply.
  • System > Certificates > Block Page CA: create, replace, delete; download as .cer (Windows / Group Policy) or .crt (PEM), with Group Policy steps. The CA key stays on the firewall; a CA in use cannot be deleted.
  • System > Certificates: download the web panel certificate.

Changed

  • Engine stratum-dpi 1.2: says how far each name can be trusted (server name / payload, partial, port or address guess), what the device sent first (TLS ClientHello, QUIC Initial, other, nothing), and hands every new connection over at once (it waited in a buffer before).
  • A connection whose server name is known is named at once instead of after nDPI's packet limit.
  • When nDPI only guessed a name from the port or address, the server name wins.
  • Apply reloads the collector's blocks after a pf reload.
  • Unbound: the web filter's and Application Control's tags are merged into one list per network.
  • Firefox is told not to switch to DNS over HTTPS while a rule shows the block page.

Security

  • The block page server runs as its own unprivileged user (_stratumbp), only it and root can read the CA key, and its ports cannot be reached directly from any network.

0.1.0 - 2026-10-29

First release.

  • FreeBSD-based firewall with a web panel (HTTPS) and a dashboard.
  • One central configuration file, applied with automatic rollback.
  • Console menu and first-boot setup wizard.
  • Installer ISO: GPT for BIOS and UEFI, ZFS, fully offline installation.

Source Availability & Licensing

Stratum Firewall is built on audited open-source foundations (FreeBSD 15.1, pf, OpenZFS, Suricata, Unbound, WireGuard, strongSwan, nDPI) and is distributed completely free at $0/year with zero user, device, or tunnel limits. Core FastAPI panel sources remain in a private repository during active development, while the 48-chapter User Manual, changelogs, and issue tracking are public on GitHub.
