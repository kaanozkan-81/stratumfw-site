After completing [initial configuration](/resources/documentation/initial-configuration/), the Stratum Gateway panel is your primary interface for managing every aspect of the firewall. This tour walks through the layout, navigation, and the patterns shared across all modules so you can find your way around quickly.

## Accessing the Panel

Open a browser and navigate to the LAN address of your gateway:

    https://192.168.1.1

The panel uses a self-signed certificate generated by the **Local CA** module during first boot. Your browser will warn you about the certificate — this is expected. Accept the exception to proceed (or import the CA certificate from the Local CA module for a trusted setup).

### Logging In

    Username: admin
    Password: (shown on the console during first boot)

On first login, the panel **forces a password change**. The initial password is also stored at **/root/STRATUM_INITIAL_LOGIN.txt** on the appliance for reference. Choose a strong password — it will be required for all subsequent logins and for SSH access.

> **Tip:** There is no password recovery mechanism. If you lose the admin password, you will need console access to reset it via the CLI.

## The Dashboard

The dashboard is the first screen after login. It is designed to answer three questions at a glance:

1. **Is the system healthy?**
2. **What is happening on the network right now?**
3. **Are there any alerts I need to act on?**

### Top Bar

The top bar contains:

| Element | Purpose |
|---------|---------|
| **Stratum logo** | Click to return to the dashboard from anywhere |
| **Hostname** | The configured system hostname |
| **Version badge** | Current running version (e.g. v1.3.0) |
| **Notifications** | Bell icon — surfaces unread alerts from IDS, CrowdSec, updates, and system events |
| **User menu** | Password change, logout, and session info |

### Status Cards

The dashboard shows a grid of status cards, each summarising one subsystem:

- **System** — CPU, memory, uptime, load average
- **Interfaces** — link state and IP addresses for each WAN/LAN interface
- **Multi-WAN** — active gateway, failover state, latency to each upstream
- **Firewall** — active rule count, recent blocks
- **IDS (Suricata)** — alert count over the last 24h, top signatures
- **CrowdSec** — active decisions, banned IP count
- **VPN (WireGuard)** — connected peers, traffic totals
- **DHCP** — active leases, pool utilisation
- **DNS** — query rate, cache hit ratio, blocked queries (RPZ)

Clicking any card opens the corresponding module. This is the fastest way to jump into the area you need.

## The Navigation Sidebar

The left sidebar is the primary navigation. Modules are grouped into six categories matching the product architecture:

### Network & Connectivity

- **Interfaces** — physical and VLAN interface configuration
- **Multi-WAN** — failover, load balancing, health checks
- **DHCP (Kea)** — pools, reservations, static leases
- **DNS (Unbound + RPZ)** — resolver, forwarders, blocklists
- **NAT** — source NAT, port forwarding, 1:1 NAT

### Security & Threat Protection

- **Firewall Rules & Objects** — policy rules, aliases, groups
- **Suricata IDS** — interface selection, rulesets, alerts
- **CrowdSec** — community blocklists, decisions, scenarios
- **Geo / Threat IP Blocking** — country and reputation feeds
- **Web Filtering (DNS)** — categories, custom allow/deny

### Access & Identity

- **WireGuard VPN** — peers, keys, QR codes
- **Captive Portal** — guest access, templates, RADIUS
- **RADIUS** — authentication backend for portal and panel

### Traffic Control

- **QoS (HTB + CAKE)** — bandwidth shaping and fairness
- **NetFlow** — flow export to collectors

### Management & Operations

- **Backup / Restore** — module-level and full-system snapshots
- **Updates** — manual check, scheduled updates, rollback
- **Notifications** — email/webhook alert routing
- **SNMP** — monitoring integration
- **Web Terminal** — browser-based shell on the appliance

### Platform & Foundation

- **Local CA** — certificate authority, issued certs
- **Users** — panel accounts, roles, API keys
- **System Settings** — hostname, timezone, NTP, logging

## Common Patterns Across Modules

Every module follows the same interaction pattern. Once you learn it in one place, you know it everywhere.

### Status Indicators

Colour-coded badges appear next to most settings:

| Colour | Meaning |
|--------|---------|
| Green | Active, healthy, applied |
| Amber | Pending change — not yet applied |
| Red | Error, down, or misconfigured |
| Grey | Disabled or not applicable |

### Apply vs. Save

Two different actions exist and they are not the same:

- **Save** — writes your changes to the configuration store. Nothing takes effect yet.
- **Apply** — pushes the saved configuration to the running system and reloads services.

This two-step model lets you stage multiple changes (for example, several firewall rules) and apply them together. A yellow "pending changes" banner appears in the top bar whenever there is unapplied configuration.

> **Important:** Rebooting with unapplied changes will discard them. Always click **Apply** before leaving a module.

### Validation

Forms validate on blur. Invalid fields are highlighted in red with an inline explanation. The **Apply** button stays disabled until every field passes validation, preventing broken states from reaching the running system.

### Change Log

Every apply is recorded with a timestamp, the user who made the change, and a diff. Open **System Settings → Change Log** to review or roll back recent configuration changes.

## Searching and Shortcuts

The sidebar has a search box at the top. Start typing a module name and press Enter to jump directly to it. A few useful shortcuts:

- **g d** — go to Dashboard
- **g r** — go to Firewall Rules
- **g v** — go to WireGuard VPN
- **?** — show the full shortcut reference

Shortcuts work as long as focus is not inside a text input.
